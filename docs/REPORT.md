# LinguaForge 研究報告 — Qwen3.5 繁中／英／日翻譯特化微調

> 單張 RTX 3070 Ti 8GB，把 `Qwen/Qwen3.5-0.8B` LoRA SFT 成 zh-TW ↔ en ↔ ja 六方向翻譯模型。
> 完整分數表 `results/scoreboard.md`；本文為實驗全紀錄與結論。

## 摘要

- **核心問題不是語意、是字形**：0.8B 的語意理解已堪用（COMET 82–86），但翻中文時大量摻簡體（FLORES ja→zhtw 洩漏 **45.6%**）。這是 SFT 最能補的地方。
- **v3（0.8B）成果**：簡體洩漏 20.8%/45.6% → **5.2%/6.0%**，COMET 均分 83.85 → **84.80**，六方向 5 升 1 微降；eval_loss 1.988（跌破 v2 的 2.163）。
- **關鍵翻轉**：補測官方 **Qwen3.5-2B 零樣本**後發現其 COMET 每基準都 > 我們的 2B QLoRA 微調版；**最高品質、零訓練的出貨組合是「官方 2B + s2twp 後處理」**（FLORES COMET 88.21、洩漏 5.4%）。
- **量化稅研究**：微調與量化正交、可疊加——**v3 在任一精度都勝官方 bf16**，且台灣正體字形在 4-bit 下幾乎零損失。

## 1. 動機與問題定義

需求：本機、低成本、純開源語料，做一個能雙向翻 **繁體中文（臺灣用語）↔ 英文 ↔ 日文** 的小模型。基座選 `Qwen/Qwen3.5-0.8B`（873M，Apache-2.0，`qwen3_5` 混合線性注意力 + 視覺塔多模態架構，用 `AutoModelForImageTextToText` 載入）。

零樣本地板診斷出兩個真正的病灶：
1. **簡體洩漏**：中文目標方向大量輸出簡體字（ja→zhtw 45.6%、en→zhtw 20.8%）。
2. **日文互譯表面品質偏弱**：en→ja / zhtw→ja 的 chrF++/BLEU 明顯低。

語意（COMET）本身不差 → 微調策略聚焦「字形正確 + 日文方向補強」，而非硬拚語意天花板。

## 2. 資料

六方向各 ~130k、合計 **773,389** 句訓練樣本（dev 每方向 200）。

| 來源 | 方向 | 角色 |
|---|---|---|
| COCT（Taiwan Panorama） | en↔zhtw | 原生臺灣正體，品質最佳 |
| TED2020 | en↔zhtw / ja↔zhtw / en↔ja | 乾淨完整句 |
| WikiMatrix / JParaCrawl / KFTT / Tatoeba / News-Commentary | en↔ja | 書面體，貼 FLORES domain |
| GlobalVoices（原生繁新聞）/ KDE4（原生繁 IT） | en/ja↔zhtw | v3 新增，補新聞/在地化語域 |
| OpenSubtitles / MTNT | →en 源側 | v3 新增，救 into-English 崩（僅進源側，護洩漏戰果） |

清洗流程：控制字元正規化 → 字幕雜訊剝除 → 長度與長度比過濾 → 語言驗證（假名/漢字/ASCII 比例）→ **OpenCC `s2twp` 統一臺灣正體** → 去重 → **免污染閘**（hash 5 個評測基準的個別語言行含 s2twp 變體共 33,984 行，訓練對任一側命中即丟）。

> 污染稽核結果：v2 舊來源命中僅 ~0.3%（多為短句通用語碰撞）→ **v2 沒實質背考卷**，多領域診斷結論成立；v3 起污染歸零。

## 3. 評測方法

- **基準**：FLORES-200 devtest（維基書面）、NTREX-128（新聞·原生繁）、WMT22（多領域）、ALT（Wikinews）、TICO-19（醫療，最終封存開封一次當背課本偵測器）。六方向各 500 句、greedy。
- **指標**：chrF++ / BLEU（sacrebleu，日文 `ja-mecab`、中文 `zh`）＋ COMET（`Unbabel/wmt22-comet-da`，隔離環境）＋ **簡體洩漏率**（OpenCC `s2t` round-trip）。
- **紀律**：COMET 對簡繁不敏感（會獎勵洩漏簡體卻流暢的輸出）→ **COMET 與洩漏率必須並看**；原生繁體參考（FLORES/NTREX）與 s2twp 轉換參考（WMT/ALT/TICO）不可跨基準平均。

## 4. 迭代演進（0.8B）

| 版本 | 關鍵改動 | FLORES COMET 均 | 洩漏 en→zhtw / ja→zhtw |
|---|---|---|---|
| base（官方零樣本） | — | 83.85 | 20.8% / 45.6% |
| v1 | r32/α64、en↔ja 用 OPUS-100 | 83.06 | 8.2% / 5.8% |
| v2 | en↔ja 換乾淨書面語料 | 84.58 | 6.4% / 6.4% |
| **v3** | r64/α128 + NEFTune + 多領域 + 污染閘 | **84.80** | **5.2% / 6.0%** |

- **v1 教訓**：洩漏修好了，但 COMET −0.75、日文方向退步——根因是 OPUS-100 日文口語/雜訊與 FLORES 書面體 domain 不匹配（非「翻譯特化的固有 trade-off」）。
- **v2 修正**：換乾淨日文語料重訓，COMET 反超 baseline +0.77，en→ja **+2.9**。
- **v3 定案**：多領域強化 + NEFTune，最弱的 zhtw→ja 跨三領域一致上升，六方向回歸守門全過。

### v3 FLORES 六方向明細

| 方向 | chrF++ (base→v3) | BLEU (base→v3) | COMET (base→v3) | 洩漏 (base→v3) |
|---|---|---|---|---|
| en→zhtw | 20.92 → 19.28 | 24.98 → 25.91 | 85.92 → 85.08 | **20.8% → 5.2%** |
| zhtw→en | 47.94 → 48.82 | 19.33 → 21.09 | 84.40 → 84.47 | — |
| en→ja | 18.79 → 20.96 | 17.43 → 19.31 | 83.20 → **85.55** | — |
| ja→en | 45.37 → 48.06 | 16.01 → 19.80 | 83.82 → 84.89 | — |
| ja→zhtw | 11.66 → 15.32 | 10.42 → 20.83 | 82.69 → **84.74** | **45.6% → 6.0%** |
| zhtw→ja | 14.95 → 17.12 | 12.05 → 15.41 | 83.07 → 84.09 | — |

> 唯一 tradeoff：en→zhtw COMET −0.84——輸出台灣用語與 FLORES 參考特定字詞有落差，略拉低表面分，換來洩漏 20.8%→5.2%。

## 5. 多領域診斷（v3 Phase A，關鍵方法論）

只有 FLORES 一張考卷時，任何「提升」都無法否證是不是過擬合到它。擴到 5 基準後（以 NTREX 這個「原生繁體但新聞領域」當最乾淨判據）：

1. **確有 FLORES 過擬合，但非全面崩**：NTREX 六方向一致低於 FLORES −1.3~−5.8（真領域退化）。
2. **醫療(TICO)、Wikinews(ALT) 反而穩** → 過擬合針對新聞語域，非所有 OOD。
3. **WMT into-English 崩**（ja→en 76.8、zhtw→en 77.8）→ **源側解析弱**：生成英文沒問題，解析口語/雜訊的 ja/zh 源吃力。
4. **zhtw→ja 全領域一致最低** → 領域無關的真弱點（呼應 2B 診斷）。
5. **簡體洩漏全領域穩健**（3~8%，OOD 也守）→ 字形修正泛化良好。

TICO 封存開封驗證：勝者 dev−sealed 差距 ~0.8 → 真泛化、非背課本。

## 6. 2B 對照與出貨決策

並行訓練 2B QLoRA（NF4 4-bit，8GB 唯一塞得下的方式）作能力 vs 資料的診斷。補測官方零樣本地板後出現**關鍵翻轉**：

| 基準（COMET） | 官方0.8B | 官方2B | v2 | v3-0.8B | v3-2B |
|---|---|---|---|---|---|
| flores | 83.85 | **86.98** | 84.58 | 84.80 | 86.33 |
| ntrex | 79.97 | **84.10** | 81.45 | 81.42 | 83.42 |
| wmt22 | 80.85 | **83.96** | 80.58 | 80.97 | 82.72 |
| alt | 82.81 | **86.66** | 84.48 | 84.94 | 86.31 |

- **官方 Qwen3.5-2B 零樣本 COMET 每基準都 > v3-2B**；洩漏用既有 s2twp 後處理即可修：**「官方 2B + s2twp」FLORES COMET 88.21、洩漏 5.4%（過閘）** → **最高品質、零訓練的出貨組合**。
- **但「2B 微調淨負」被 NF4 2×2 實驗否證**：`base bf16 86.98 →(量化 −0.69)→ base NF4 86.29 →(同精度微調 −0.06 ≈ 中性)→ v3 NF4 86.23`。**那 0.65 差距主因是被 8GB 逼用 4-bit QLoRA 的量化稅，非微調本身破壞品質**。真正判定 2B 微調價值需全精度 bf16 訓 2B（雲端 >8GB，未做）。
- **0.8B 微調仍有正價值**：輕量部署場景，COMET 小升 + 洩漏 20/47%→5/6%。

## 7. 量化稅研究（0.8B，FLORES COMET 均，n=500）

微調與量化**正交、可疊加**：量化收一筆固定的稅，微調給一筆固定的補貼。

| 精度 | 官方 0.8B | v3-0.8B |
|---|---|---|
| bf16 | 83.85 | **84.80** |
| int8 (LLM.int8) | 83.65（−0.20） | 84.75（−0.05） |
| nf4 (4-bit) | 82.08（−1.77） | 83.25（−1.55） |

- **同精度微調增益 ~+1.0，不隨精度衰減**（bf16 +0.95 / int8 +1.10 / nf4 +1.17）。
- **v3 任一精度都勝官方 bf16**：v3-int8（84.75）> 官方-bf16（83.85）；int8 是「抵消還有賺」，4-bit 是「抵消大半」。
- **台灣正體字形在量化下幾乎零損失**（離散 token 偏好，不靠權重精度）：

| 精度 | v3 en→zhtw 洩漏 | v3 ja→zhtw 洩漏 |
|---|---|---|
| bf16 | 5.2% | 6.0% |
| int8 | 5.0% | 5.8% |
| nf4 | 5.0% | 5.6% |

→ **v3-nf4（4-bit）在字形正確性上完勝官方-bf16（16-bit）**。結論：微調讓你敢放心量化。

## 8. 結論

1. **0.8B 微調的價值在字形與用語，不在語意天花板**：v3 把簡體洩漏壓到 5–6% 且泛化到所有領域，COMET 均分不降反升。
2. **8GB 的天花板是量化稅，不是微調無效**：2B 只能 4-bit QLoRA，量化稅（−0.69）汙染了「微調有無價值」的判定；乾淨結論需雲端 bf16 重訓。
3. **最高品質出貨 = 官方 2B + s2twp**（零訓練，COMET 88.21）；**最輕量出貨 = v3-0.8B（本開源版）**，int8/4bit 量化下仍勝官方 bf16。
4. **方法論教訓**：微調前先量官方零樣本地板；單一基準無法否證過擬合，多領域 + 封存集才能判泛化。

```powershell
uv run python scripts/download_data.py                       # 語料（冪等）
```
